## Question

The stack is locked: **full-TypeScript monorepo, Next.js + Yjs/Hocuspocus + Postgres + S3, Docker-deployed.** This ticket resolves the **shape of the repo** so a builder knows where everything lives. This is mostly laying out the structure the other tickets' decisions live inside.

1. **Monorepo tool.** Pick **pnpm workspaces + Turborepo** (recommend) or **Nx**. Rationale: pnpm + Turbo is the current default for TS app monorepos; lightweight, fast caching. Confirm.
2. **Layout.** Propose the package/app split. Recommended:
   ```
   apps/
     web/            # Next.js app (UI + REST/route handlers + BlockNote editor)
     realtime/       # Hocuspocus WebSocket server (long-lived process)
     worker/         # (optional) background jobs — thumbnail gen, quota recompute
   packages/
     db/             # Prisma/Drift schema + client (shared by web + realtime + worker)
     auth/           # session/cookie helpers, RBAC permission engine (shared)
     shared/         # types, zod schemas, Yjs block schema shared across apps
     ui/             # shared React components (sidebar, cmd+K palette, block blocks)
     config/         # eslint/tsconfig/tailwind presets
   ```
   Confirm or adjust. Key decision: **is the Hocuspocus server a separate app/process or a route inside Next.js?** Recommend **separate** (`apps/realtime`) — it's a long-lived WebSocket process, doesn't fit Next.js's request model, and must be independently scalable.
3. **DB layer.** Confirm **Prisma** (recommend — TS-first, schema-as-source-of-truth, migrations) or **Drizzle** (lighter, more SQL-native). State the choice; it owns the schema defined in ticket 0003.
4. **Type & runtime safety.** Confirm: **TypeScript strict** everywhere, **Zod** for runtime validation at API boundaries, types generated from the Zod schemas in `packages/shared`.
5. **Env config.** Confirm a single-source `packages/config/env.ts` (Zod-validated `process.env` schema) consumed by all apps — so missing/invalid env fails at boot, not at runtime.
6. **Local dev.** Confirm `docker-compose.yml` at repo root running Postgres + MinIO (+ the app via the dev server), with seeded dev data. One-command `pnpm dev`.
7. **Testing baseline.** State the v1 testing bar: **Vitest** for unit (especially the permission engine in `packages/auth`), **Playwright** for e2e of the editor flow. No hard coverage gate for v1 — but the permission engine *must* have unit tests (it's the security boundary).

**Resolve by:** `/grilling`. Output: the chosen monorepo tool + DB layer, the confirmed directory layout (with the realtime-separate-process decision explicit), the env/config approach, the local-dev compose setup, and the testing baseline. ## Resolution — 2026-07-28

All seven questions resolved. This is the **repo skeleton** the build effort
populates. With this and the now-closed 0002/0003/0004/0005/0006/0007/0008, a
builder can scaffold the whole project.

### Decisions locked

1. **Monorepo tool: pnpm workspaces + Turborepo.** pnpm for fast, disk-efficient
   installs and strict hoisting (matters when web/realtime/worker share Prisma,
   Yjs, Better Auth); Turborepo for cached, parallel task orchestration across
   apps/packages. One `turbo.json`.
2. **Layout** — confirmed (with the realtime-as-separate-process fork resolved):
   ```
   apps/
     web/            Next.js (App Router): UI + REST/route handlers + BlockNote editor
     realtime/       Hocuspocus WebSocket server (separate long-lived process;
                     runs onAuthenticate -> packages/auth can_read)
     worker/         (optional) bg jobs: thumbnail gen, quota recompute, trash purge
   packages/
     db/             Prisma schema.prisma (source of truth, ticket 0003) + generated client
     auth/           Better Auth config + the RBAC permission engine (can_read,
                     effective-permission CTE, owner/admin bypass, union rule)
     shared/         types + Zod schemas (API boundaries) + Yjs block schema + embed resolver
     storage/        S3-compatible client + presigning (ticket 0007) + SMTP transport (0006)
     ui/             shared React components (sidebar, cmd+K palette, block components)
     config/         eslint/tsconfig/tailwind presets + the Zod-validated env schema
   ```
   **Hocuspocus is a separate process** (`apps/realtime`), NOT a route inside
   Next.js — it's a stateful, long-lived WebSocket server that doesn't fit
   Next.js's per-request lifecycle, and it must scale/restart independently
   (matches the Docker/self-hostable topology and ticket 0004's findings).
3. **DB layer: Prisma.** TS-first, schema-as-source-of-truth
   (`packages/db/schema.prisma`), generated typed client, migrations. The
   ticket-0003 schema maps ~1:1 to a Prisma schema. Generated client lives in
   `packages/db`, imported by web/realtime/worker/auth.
4. **Type & runtime safety:** **TypeScript strict** everywhere; **Zod** for
   runtime validation at all API boundaries, with types derived from the Zod
   schemas in `packages/shared` (single source for request/response shapes).
5. **Env config:** single-source `packages/config/env.ts` — a Zod-validated
   `process.env` schema consumed by all apps, so missing/invalid env **fails at
   boot**, not at runtime. Consolidates every env var surfaced across tickets
   (`DATABASE_URL`, `AUTH_SECRET`, OAuth creds, `S3_*`, `SMTP_*`, quotas,
   `HOCUSPOCUS_*`).
6. **Local dev:** `docker-compose.yml` at repo root running **Postgres + MinIO**
   (+ the apps via dev servers), with seeded dev data (a workspace, users,
   sample pages). One-command `pnpm dev` (Turborepo runs web + realtime + worker
   + the compose deps).
7. **Testing baseline:** **Vitest** for unit/integration + **Playwright** for
   e2e. **Hard requirement:** `packages/auth` (the permission engine) has
   thorough unit tests — it's the security boundary (`can_read`,
   effective-permission CTE, owner/admin bypass, union rule, group resolution).
   Beyond that: API route handlers get integration tests against a test DB; the
   editor + realtime collaboration gets a small Playwright e2e suite
   (two-browser multi-user edit, share flow). **No hard coverage gate for v1.**

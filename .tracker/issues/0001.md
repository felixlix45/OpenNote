# [MAP] OpenNote v1 — finding the way to a build-ready spec

- **Label:** `wayfinder:map`
- **Status:** open
- **Parent:** _(this is the map)_
- **Blocking:** _(none)_

## Destination

A **build-ready spec + architecture** for OpenNote v1 — a self-hostable, multi-tenant, real-time, Notion-style notes app. When the map closes, every major decision (stack, editor, data model, permission engine, auth, attachments, deployment, search) is resolved and a builder can start writing code with no open architectural questions. Implementation itself happens in a *follow-up* effort, not inside this map.

## Notes

- **Domain:** real-time collaborative block editor, multi-tenant (workspaces + groups), self-hostable.
- **Skills every session should consult:** `/grilling` + `/domain-modeling` for permission/engine decisions; `/research` for library deep-dives (Yjs persistence, Hocuspocus auth hooks, BlockNote custom blocks); `/prototype` for the permission-engine and Yjs-persistence questions where a rough artifact settles the decision.
- **Standing preferences:**
  - Full-stack **TypeScript monorepo** (types shared end-to-end).
  - Prefer **self-hostable**, dependency-light choices (no forced cloud services).
  - Source of truth for page body is the **Yjs document**, not a normalized blocks table.
  - **RBAC is the full Notion model**: workspaces, roles, groups, per-resource shares with inheritance.
  - Decisions, not deliverables — this map plans; it does not build.

## Decisions so far

<!-- One line per closed ticket: enough to judge relevance, then zoom the link for detail -->

- [0002 — Permission & sharing model](./issues/0002.md) — 4 workspace roles (Guest/Member/Admin/Owner), 3 share levels (Reader/Commenter[reserved]/Editor), **union inheritance** (strongest grant wins, no Deny), live group resolution, open-workspace rule (implicit all-members→Editor on root), guests via per-resource share, no public links in v1. Algorithm + downstream impact recorded on the ticket.
- [0004 — Real-time layer](./issues/0004.md) — `@hocuspocus/extension-database` writes `Y.encodeStateAsUpdate` bytes to `page_docs.state bytea`; server debounce defaults (2s/10s) + graceful-shutdown flush; auth in `onAuthenticate` returning `{user,pageId,role}` + `connection.readOnly`; doc name `page:{pages.id UUID}`; awareness/cursors free; single instance fine for v1, `extension-redis` post-v1. Findings: `research/0004-realtime-layer.md`.
- [0003 — Data model](./issues/0003.md) — full relational schema: global `users`, `workspaces`/`workspace_members`/`groups`/`group_members`, adjacency-list `folders`/`pages` (nested via `parent_page_id`), `page_docs.state bytea`, two-FK `shares` table, soft-delete + Trash, `attachments`, `workspace_invites`. Includes the effective-permission recursive CTE and the index plan. Decisions: adjacency list + recursive CTE; `pages.title` mirrored from doc; two nullable FKs for share principals; `deleted_at` Trash w/ 30-day purge; global identity.
- [0008 — Search](./issues/0008.md) — Postgres FTS via stored generated `search_tsv` (title weight A) + GIN; **inline** permission scoping (join against the effective-permission CTE); accept **~10s lag** (update `body_text` in the same debounced `onStoreDocument` path); cmd+K palette showing title+breadcrumb+snippet; Postgres-only, no external search infra in v1.
- [0007 — Attachments](./issues/0007.md) — S3-compatible (AWS SDK v3; MinIO self-host default / R2/S3 managed); presigned PUT direct-to-S3 upload; **25 MB/file, 5 GB/workspace** env-tunable quotas; short-lived signed GET URLs (10-min TTL) minted after `can_read`; permissive MIME/extension allowlist, no AV in v1; image blocks inline + file blocks w/ download; SVG/HTML forced to `Content-Disposition: attachment` (stored-XSS).
- [0006 — Auth](./issues/0006.md) — **Better Auth** (Lucia deprecated, Auth.js v5 beta → research recommended Better Auth): built-in email/pw + OAuth + DB-backed cookie sessions, self-hostable. Global identity (one account, many workspaces). Any user can create a workspace; first sign-up bootstrapped as Owner of a default "OpenNote" workspace. Invite links (token, 7-day, revocable). SMTP email in v1 (reset + invites) with in-app fallback. Findings: `research/0006-auth-libraries.md`.
- [0005 — Block editor scope](./issues/0005.md) — BlockNote defaults + custom **sub-page** (nested pages, backend owns the `parent_page_id` edge), **file**, **callout**, **toggle**, **@mention** (@user via member/group queries, @page via the FTS index), **embed** blocks. Formatting: 6 marks **+ color + highlight** (user deliberately widened v1 scope beyond the original feature list). Markdown input/paste on. Mentions are inert references (no notifications in v1).
- [0009 — Monorepo & structure](./issues/0009.md) — **pnpm workspaces + Turborepo**; layout `apps/{web,realtime,worker}` + `packages/{db,auth,shared,storage,ui,config}`; **Hocuspocus is a separate process** (`apps/realtime`); **Prisma** owns the schema; TS strict + Zod at API boundaries; single Zod-validated env schema; root `docker-compose.yml` (Postgres + MinIO + seeded data), `pnpm dev`; **Vitest + Playwright**, permission engine must be unit-tested. **Unblocks the build.**

## Not yet specified

The fog toward the destination — in scope, not yet sharp enough to ticket. Graduates into tickets as the frontier advances.

### Permission engine
- **Realtime authorization mechanics** (the one piece still open here): ticket 0010 owns the gating-point design. The research (0004) surfaced that Hocuspocus has **no built-in periodic re-auth** — so v1's "live revocation" is reconnect-based (accepted-stale), and a true periodic re-check is deferred to post-v1. The exact re-check interval and the share-change→connection-kill mechanism (if any in v1) still need 0010 to pin down.

### Yjs persistence & sync
- **Page-vs-doc mapping confirmed:** one Y-doc per page (decided, ticket 0004). Doc name = `page:{pages.id UUID}`. Persistence via `@hocuspocus/extension-database` → `page_docs.state bytea`.
- **Title location settled (ticket 0003):** `pages.title` is a denormalized mirror refreshed from the Y-doc on save (same pattern as `body_text`).
- **Offline / reconvergence:** is offline editing in scope, or always-online? (CRDTs make offline possible; v1 may still choose to disable it.) — still open, low priority.

### Block editor scope
- **All settled (ticket 0005):** BlockNote defaults + custom sub-page/file/callout/toggle/@mention/embed blocks; 6 marks + color/highlight; nested pages in v1 (backend owns the tree edge); mentions inert (no notifications). **Note:** user deliberately widened v1 editor scope beyond the original feature list.

### Workspace & content model
- **Workspace top level settled (ticket 0003):** root = `parent_id NULL`; the implicit all-members→Editor share uses `resource_id NULL` as the workspace-root sentinel. Sidebar renders via `folders_children_idx` / `pages_folder_idx` (paginated/deferred for large workspaces is a post-v1 concern).
- **Soft-deletion / trash settled (ticket 0003):** `deleted_at` on folders + pages, Trash view, 30-day auto-purge job.
- **Page history / versioning:** out of scope for v1. (CRDT history is technically available; exposing it is work.) — remains out of scope.

### Auth & onboarding
- **All settled (ticket 0006):** **Better Auth** (Lucia deprecated, Auth.js v5 beta); global identity; any user creates workspaces, first sign-up bootstrapped as Owner of a default workspace; invite links (token, 7-day); SMTP email in v1 for reset + invites with in-app fallback.

### Attachments
- **All settled (ticket 0007):** S3-compatible (MinIO self-host default / R2/S3 managed); presigned PUT direct-to-S3; 25 MB/file + 5 GB/workspace env-tunable quotas; short-lived signed GET URLs minted after `can_read`; permissive allowlist, no AV in v1; SVG/HTML forced to download (stored-XSS mitigation).

### Search
- **Index freshness settled (ticket 0008):** ~10s lag accepted; `body_text` + the generated `search_tsv` update in the same debounced `onStoreDocument` path as Y-doc persistence. Scoping is inline against the effective-permission CTE.

### Cross-cutting
- **Testing strategy settled (ticket 0009):** Vitest unit/integration + Playwright e2e; permission engine (`packages/auth`) must be unit-tested; no hard coverage gate.
- **Project structure settled (ticket 0009):** pnpm + Turborepo, `apps/{web,realtime,worker}` + `packages/{db,auth,shared,storage,ui,config}`, Prisma, Hocuspocus as a separate process, Zod env schema, root docker-compose.
- **Observability:** logging/metrics/error-tracking baseline for v1 — still open, low priority (a minimal structured-logging baseline is enough for v1; defer metrics/APM to post-v1).

## Out of scope

Work consciously ruled out beyond the v1 destination. Does not graduate; returns only if the destination is redrawn.

- **Real-time is IN scope** (decided) — but *mobile clients / native apps* are out; v1 is a web app only.
- **AI features** (summarize, Q&A, autocomplete) — out of v1.
- **Advanced search** including content inside attachments (OCR / document parsing) — out of v1.
- **Rich attachment previews** (PDF/video/Office inline players) and **file versioning/history** — out of v1.
- **Public internet publishing** of pages (Notion's "publish to web") — out of v1; only authenticated sharing.
- **Email/notification system** (mentions, comments, change notifications) — out of v1.
- **Comments / discussions** on blocks — out of v1.
- **Custom themes / branding per workspace** — out of v1.

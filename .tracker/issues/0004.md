## Question

The stack is locked: **Yjs + Hocuspocus** as the real-time engine, **BlockNote** as the editor, one **Y-doc per page** persisted somehow, deployed as **long-lived processes** (Docker). This ticket resolves the **mechanics of the realtime layer** so a builder knows exactly what to wire. Questions to answer with research into current Hocuspocus/Yjs docs (not assumptions):

1. **Persistence adapter.** What is the recommended way to persist Y-docs in v2024+ Hocuspocus? Confirm whether to (a) store the binary doc in Postgres `bytea` via a custom `onStoreDocument`/`onChange` handler, (b) use the official Postgres/Redis/LevelDB extensions, or (c) a hybrid (updates streamed to a log, periodic snapshot). State the chosen approach with a link to the doc that supports it.
2. **Save cadence / batching.** Hocuspocus fires on every update. What's the recommended debounce/coalescing so we don't write to Postgres on every keystroke? What's the worst-case data-loss window if the server dies between snapshot saves?
3. **Authentication hook.** Confirm the exact hooks (`onAuthenticate`, `onListen`?) and what they receive — specifically how to read "which page doc" and "which user" from the connection context, so the effective-permission algorithm from ticket 0002 can gate access on connect *and* on load. Note any hook ordering pitfalls.
4. **Doc identity.** How does the client address a page's Y-doc (a doc name = page id / slug)? What's the recommended naming scheme and how does it map back to the `pages` row?
5. **Awareness/presence.** Out of the box, does Hocuspocus relay awareness (cursors, selections, who's-online) without extra wiring? Confirm so the product team knows whether live cursors are free or need work.
6. **Scaling ceiling.** What does Hocuspocus's single-process model mean for v1 scale? When does sticky-session / horizontal sharding by doc-name become necessary, and is that a v1 concern or safely post-v1?

**Resolve by:** `/research` subagent reading current Hocuspocus + Yjs docs and the BlockNote collaboration example. Output: a short findings doc (linked as an asset) answering each numbered question with a citation, plus a recommendation per item. This is AFK research — no human decision needed unless it surfaces a fork the map must escalate.

# Data model: relational schema for workspaces, groups, folders, pages, attachments, RBAC

- **Label:** `wayfinder:grilling`
- **Status:** closed (resolved 2026-07-28)
- **Parent:** [0001 — MAP](./0001.md)
- **Blocking:** [0008](./0008.md), [0010](./0010.md) — and **blocked by** [0002](./0002.md) ✓resolved
- **Assignee:** ZCode (working the map)

## Question

Given the locked decisions — **hybrid storage** (one Y-doc per page is the source of truth for body content; PostgreSQL holds the tree + RBAC + a denormalized `body_text` for search), **multi-tenant workspaces with groups and permission inheritance** — this ticket resolves the **exact relational schema** for v1. Produce SQL-level table designs (columns, types, foreign keys, indexes) and the rationale for each non-obvious choice.

Tables to design (at minimum):

1. **`users`** — global account vs. workspace-scoped identity (see fog; this ticket should propose, the auth ticket should confirm). Profile fields, credentials reference (auth library owns password hashing).
2. **`workspaces`** — the tenant boundary. Owner, name, slug, plan/quota fields.
3. **`workspace_members`** — user × workspace × role (the join that resolves "who's in this workspace and as what").
4. **`groups`** and **`group_members`** — groups live inside a workspace; many-to-many with users.
5. **`folders`** — `parent_id` self-reference for nesting; belongs to a workspace.
6. **`pages`** — `folder_id` *and/or* `parent_page_id` (nested pages); `title`; references its Y-doc.
7. **`page_docs`** — `page_id → Yjs binary blob` (the editor's source of truth). Decide: `bytea` column vs. separate blob table; how updates are written.
8. **`shares`** — the ACL rows: `(resource_type, resource_id) × (principal_type, principal_id) × role/permission`. Encodes the inheritance model from ticket 0002.
9. **`attachments`** — `id, page_id, s3_key, filename, mime, size, uploaded_by`. Links to the file block in the doc by id.
10. **Search support** — `pages.body_text` + a `tsvector` index; trigger to keep it fresh on save.

Decisions to land here:

- **Title location:** is the page title stored in the `pages` row, in the Y-doc, or both (and reconciled which way)? State the choice and the reconciliation direction.
- **Tree representation:** adjacency list (`parent_id`) confirmed, vs. materialized path / closure table — pick one with rationale for the sidebar-tree and permission-inheritance queries it must serve.
- **Principal polymorphism:** how to model `shares.principal` pointing at either a user or a group (polymorphic FK, or two nullable FKs, or a `principal_type` discriminator) — pick and justify.
- **Soft-delete:** do folders/pages get a `deleted_at` (trash) or hard-delete? (See map fog; this ticket decides it as a schema concern.)
- **Indexing strategy** for the two hot paths: (a) sidebar tree render ("children of folder F in workspace W"), (b) effective-permission check ("all shares on the path from workspace root to page P").

**Resolve by:** `/grilling` + `/domain-modeling`. The output is a schema spec (table-by-table) that a builder can turn into migrations, plus the named decisions above explicitly answered. **Blocked by ticket 0002** — the inheritance/role rules determine the shape of `shares` and the indexes that serve them.

## Notes

- This schema is what every backend query and every permission check reads. Getting the tree representation and the shares shape right here prevents painful migrations later.
- The Y-doc (`page_docs`) is deliberately out of relational normalization — do not decompose it into block rows (that decision is already made and recorded on the map).

---

## Resolution — 2026-07-28

Five decisions resolved via grilling; the schema below encodes them. Postgres
≥15 target. Conventions: UUID PKs (`gen_random_uuid()`), `timestamptz` for all
timestamps, `created_at`/`updated_at` on mutable rows. Prisma is the ORM
(decided in ticket 0009) — types here are SQL-level; Prisma maps directly.

### Decisions locked

| # | Decision | Choice |
|---|----------|--------|
| 1 | Tree representation | **Adjacency list** (`parent_id`) + recursive CTE for ancestor walks |
| 2 | Title location | `pages.title` is a **denormalized mirror refreshed from the Y-doc on save** (same pattern as `body_text`) |
| 3 | Principal polymorphism | **Two nullable FKs** (`principal_user_id`, `principal_group_id`) + CHECK exactly-one |
| 4 | Soft-delete | **`deleted_at` on folders + pages**, Trash view, 30-day auto-purge |
| 5 | Identity scope | **Global `users`** (one account, many workspaces) — confirms CONTEXT.md + ticket 0002 |

### Schema (table-by-table)

```sql
-- ============================================================
-- IDENTITY (global; not workspace-scoped)
-- ============================================================

users (
  id              uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  email           text NOT NULL UNIQUE,
  -- credentials live in the auth library's tables (ticket 0006);
  -- users holds identity + profile only.
  name            text,
  avatar_url      text,
  email_verified  boolean NOT NULL DEFAULT false,
  created_at      timestamptz NOT NULL DEFAULT now()
);

-- ============================================================
-- WORKSPACE / TENANCY
-- ============================================================

workspaces (
  id              uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  name            text NOT NULL,
  slug            text NOT NULL,            -- unique per deployment? see note
  storage_quota_bytes bigint,               -- NULL = unlimited (ticket 0007)
  created_by      uuid NOT NULL REFERENCES users(id),
  created_at      timestamptz NOT NULL DEFAULT now()
);

workspace_members (                          -- the role join
  workspace_id    uuid NOT NULL REFERENCES workspaces(id) ON DELETE CASCADE,
  user_id         uuid NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  role            text NOT NULL CHECK (role IN ('guest','member','admin','owner')),
  joined_at       timestamptz NOT NULL DEFAULT now(),
  PRIMARY KEY (workspace_id, user_id)
);
-- CHECK constraint or app rule: every workspace has >=1 owner (enforced in app).

-- ============================================================
-- GROUPS (workspace-scoped, many-to-many with users)
-- ============================================================

groups (
  id              uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  workspace_id    uuid NOT NULL REFERENCES workspaces(id) ON DELETE CASCADE,
  name            text NOT NULL,
  is_all_members  boolean NOT NULL DEFAULT false,  -- reserved sentinel
  created_at      timestamptz NOT NULL DEFAULT now(),
  UNIQUE (workspace_id, name),
  UNIQUE (workspace_id, is_all_members)             -- one all-members group per ws
);

group_members (
  group_id        uuid NOT NULL REFERENCES groups(id) ON DELETE CASCADE,
  user_id         uuid NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  PRIMARY KEY (group_id, user_id)
);
CREATE INDEX ON group_members (user_id);   -- serves live group lookup in perm checks
-- The all-members group auto-tracks every non-guest member: a trigger keeps
-- group_members in sync with workspace_members (add on join, remove on leave/role-change).

-- ============================================================
-- CONTENT TREE (adjacency list)
-- ============================================================

folders (
  id              uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  workspace_id    uuid NOT NULL REFERENCES workspaces(id) ON DELETE CASCADE,
  parent_id       uuid REFERENCES folders(id) ON DELETE CASCADE,  -- NULL = root
  name            text NOT NULL,
  created_by      uuid NOT NULL REFERENCES users(id),
  deleted_at      timestamptz,                                  -- soft-delete
  created_at      timestamptz NOT NULL DEFAULT now(),
  updated_at      timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX folders_children_idx ON folders (workspace_id, parent_id)
  WHERE deleted_at IS NULL;            -- sidebar: children of F in W

pages (
  id              uuid PRIMARY KEY DEFAULT gen_random_uuid(),   -- == Y-doc name
  workspace_id    uuid NOT NULL REFERENCES workspaces(id) ON DELETE CASCADE,
  folder_id       uuid REFERENCES folders(id),                  -- location in tree
  parent_page_id  uuid REFERENCES pages(id) ON DELETE CASCADE,  -- nested-page block
  -- A page has exactly one tree parent: exactly one of folder_id / parent_page_id
  -- is non-null (CHECK below). parent_page_id is for the "nested page as block"
  -- feature (ticket 0005); folder_id for top-level / folder-direct pages.
  title           text NOT NULL DEFAULT '',     -- mirror refreshed from Y-doc on save
  body_text       text NOT NULL DEFAULT '',     -- mirror for FTS (ticket 0008)
  icon            text,                         -- optional emoji icon (Notion-like)
  created_by      uuid NOT NULL REFERENCES users(id),
  deleted_at      timestamptz,
  created_at      timestamptz NOT NULL DEFAULT now(),
  updated_at      timestamptz NOT NULL DEFAULT now(),
  CHECK ( (folder_id IS NULL) <> (parent_page_id IS NULL) )      -- exactly one parent
);
CREATE INDEX pages_folder_idx ON pages (workspace_id, folder_id) WHERE deleted_at IS NULL;
CREATE INDEX pages_parentpage_idx ON pages (parent_page_id) WHERE deleted_at IS NULL;
-- FTS index (ticket 0008 owns the exact tsvector; sketched here):
--   search_tsv tsvector GENERATED ALWAYS AS (to_tsvector('simple', coalesce(title,'')||' '||coalesce(body_text,''))) STORED
--   CREATE INDEX pages_search_idx ON pages USING gin(search_tsv);

-- ============================================================
-- PAGE CONTENT (Y-doc source of truth) — per ticket 0004
-- ============================================================

page_docs (
  page_id         uuid PRIMARY KEY REFERENCES pages(id) ON DELETE CASCADE,
  state           bytea NOT NULL,            -- Y.encodeStateAsUpdate(doc) bytes
  updated_at      timestamptz NOT NULL DEFAULT now()
);
-- Read by Hocuspocus extension-database fetch(); UPSERTed on store (debounced).

-- ============================================================
-- SHARES (the ACL — two nullable FKs + CHECK exactly-one)
-- ============================================================

shares (
  id                  uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  workspace_id        uuid NOT NULL REFERENCES workspaces(id) ON DELETE CASCADE,
  resource_type       text NOT NULL CHECK (resource_type IN ('folder','page')),
  resource_id         uuid NOT NULL,           -- FK enforced by app (polymorphic target)
  principal_user_id   uuid REFERENCES users(id)  ON DELETE CASCADE,
  principal_group_id  uuid REFERENCES groups(id) ON DELETE CASCADE,
  level               text NOT NULL CHECK (level IN ('reader','commenter','editor')),
  created_by          uuid NOT NULL REFERENCES users(id),
  created_at          timestamptz NOT NULL DEFAULT now(),
  CHECK ( (principal_user_id IS NULL) <> (principal_group_id IS NULL) ),  -- exactly one
  UNIQUE (workspace_id, resource_type, resource_id, principal_user_id),
  UNIQUE (workspace_id, resource_type, resource_id, principal_group_id)
);
-- The implicit "all-members -> Editor on workspace root" rule from ticket 0002
-- is realized as: a sentinel share (resource_type='folder', resource_id = NULL
-- or a reserved root-folder id, principal_group_id = all-members group, level='editor').
-- 'resource_id = NULL' is the workspace-root sentinel; the effective-permission
-- path-walk treats NULL as the root and stops there.
CREATE INDEX shares_resource_idx
  ON shares (workspace_id, resource_type, resource_id);
CREATE INDEX shares_user_idx
  ON shares (principal_user_id) WHERE principal_user_id IS NOT NULL;
CREATE INDEX shares_group_idx
  ON shares (principal_group_id) WHERE principal_group_id IS NOT NULL;

-- ============================================================
-- ATTACHMENTS (ticket 0007 owns the details; shape sketched)
-- ============================================================

attachments (
  id              uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  page_id         uuid NOT NULL REFERENCES pages(id) ON DELETE CASCADE,
  workspace_id    uuid NOT NULL REFERENCES workspaces(id) ON DELETE CASCADE,
  s3_key          text NOT NULL,              -- opaque key in the S3-compatible store
  filename        text NOT NULL,
  mime_type       text NOT NULL,
  size_bytes      bigint NOT NULL,            -- counted toward workspace quota
  uploaded_by     uuid NOT NULL REFERENCES users(id),
  created_at      timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX attachments_workspace_idx ON attachments (workspace_id);  -- quota sum

-- ============================================================
-- INVITES (workspace onboarding — ticket 0006 owns the flow)
-- ============================================================

workspace_invites (
  id              uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  workspace_id    uuid NOT NULL REFERENCES workspaces(id) ON DELETE CASCADE,
  email           text NOT NULL,              -- invitee
  role            text NOT NULL DEFAULT 'member',  -- role on accept
  token           text NOT NULL UNIQUE,       -- opaque, expiring
  created_by      uuid NOT NULL REFERENCES users(id),
  expires_at      timestamptz NOT NULL,
  accepted_at     timestamptz,
  created_at      timestamptz NOT NULL DEFAULT now()
);
```

### Effective-permission query (the hot path, per ticket 0002)

The ancestor walk is a recursive CTE. For a **page**, the path is
`page → (parent_page_id | folder_id) → folder.parent_id → … → workspace root (NULL)`.

```sql
-- Pseudocode: collect all shares on the path from workspace root to page $P,
-- where the principal is user $U or any group $U is in, then take max(level).
WITH RECURSIVE
  groups_of_u AS (                                  -- live group membership
    SELECT group_id FROM group_members WHERE user_id = $U
  ),
  path_folders AS (                                 -- ancestor folders
    SELECT id, parent_id FROM folders WHERE id = $folderOfP
    UNION ALL
    SELECT f.id, f.parent_id FROM folders f
    JOIN path_folders pf ON f.id = pf.parent_id
  ),
  path_resources AS (                               -- the path as (type, id) pairs
    SELECT 'page'::text AS type, $P AS id
    UNION ALL
    SELECT 'folder', id FROM path_folders
    UNION ALL
    SELECT 'folder', NULL                           -- workspace root sentinel
  )
SELECT max(                                         -- strongest grant wins
  CASE s.level WHEN 'editor' THEN 3
               WHEN 'commenter' THEN 2
               WHEN 'reader' THEN 1 END
) AS effective
FROM shares s
WHERE s.workspace_id = $W
  AND (s.resource_type, s.resource_id) IN (SELECT type, id FROM path_resources)
  AND ( s.principal_user_id  = $U
     OR s.principal_group_id IN (SELECT group_id FROM groups_of_u) );
-- Owner/Admin bypass is checked first (one indexed lookup on workspace_members);
-- if role IN ('owner','admin'), return 'manage' without running the above.
-- NULL result = 'none' -> deny.
```

### Indexes serving the two hot paths (summary)
1. **Sidebar / children** — `folders_children_idx`, `pages_folder_idx`,
   `pages_parentpage_idx` (all `WHERE deleted_at IS NULL`).
2. **Effective permission** — `shares_resource_idx`, `shares_user_idx`,
   `shares_group_idx`, `group_members(user_id)`; ancestor walk via recursive CTE
   over `folders(parent_id)` (add an index on `folders(parent_id)`).

- **0009 (monorepo)** — this schema lives in `packages/db` as the Prisma

### 🔒 Security requirements (added post-resolution — see `research/SECURITY-REVIEW.md`)

These are **mandatory**, not optional hardening — a builder who implements the
schema above without them ships tenant-isolation and access-control holes:

1. **Tenant isolation on polymorphic `shares.resource_id`.** `resource_id` has
   no FK (it points at `folders` *or* `pages`), so nothing structurally prevents
   a share from referencing a resource in **another workspace**. Every
   permission/share query MUST (a) filter `shares.workspace_id = $W` and
   (b) assert the target resource's `workspace_id` matches before use. Prefer a
   structural guard: a generated/trigger-maintained column binding
   `(resource_type, resource_id) → workspace_id`, or a CHECK that the share's
   workspace equals the resource's workspace. The effective-permission CTE
   above already filters `s.workspace_id = $W` — keep that invariant in every
   query that touches `shares`.
2. **Soft-delete filter discipline.** `deleted_at IS NULL` must appear on
   **every** content query. One missed filter = access to trashed pages. Enforce
   this structurally via Prisma query middleware / a repository layer that
   injects the filter automatically, **not** per-query by hand.
3. **Shares on soft-deleted resources.** While a resource is trashed, its shares
   are inactive (the `deleted_at IS NULL` filter excludes the resource from the
   path walk). On restore, the shares reactivate — document this so a restore
   doesn't *silently* re-grant access (the restoring admin should be told).
4. **Nesting-depth cap.** Cap folder/page nesting depth (e.g. 32) — bounds the
   recursive CTE and prevents pathological-tree DoS. Enforce in the create/move
   endpoint.
5. **`page_docs.state` size cap.** Reject Y-doc updates that would push `state`
   beyond a per-page limit (e.g. 10 MB) — bounds bytea growth from malicious or
   accidental huge pastes. (Enforced in the realtime layer; the cap is a
   schema/contract concern noted here.)

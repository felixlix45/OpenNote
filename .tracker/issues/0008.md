## Question

Search is in scope for v1: a **cmd+K palette** searching page titles + body text, scoped to the pages the current user can see in their workspace, via **Postgres full-text search** on the denormalized `pages.body_text` column (already in the data model). This ticket resolves the mechanics:

1. **FTS setup.** Confirm: a `tsvector` column (or generated column) on `pages` over `title || ' ' || body_text`, with a GIN index. State the exact column expression and ranking (`ts_rank_cd`). Confirm Postgres version target (≥12 for generated columns; ≥15 preferred).
2. **Scoping by permission.** Search results must only include pages the user can *see* (per the effective-permission algorithm from ticket 0002). Two approaches:
   - **Inline:** join the search query against the resolved "visible pages" set (computed via the shares/inheritance rules) at query time.
   - **Materialized:** maintain a per-user "visible pages" view/cache.
   Decide which. Recommend **inline for v1** (simpler; the visible-set query is what the permission engine already produces for the sidebar). Confirm — and note this makes the search's performance depend on the permission query's indexing (ticket 0003).
3. **Freshness.** `body_text` is updated when the Y-doc is persisted (see ticket 0004's save cadence). Real-time edits therefore lag the index by up to the save-debounce window. Confirm this lag is **acceptable for v1** (search finds text "soon after" it's typed, not on every keystroke). If unacceptable, the alternative is hooking the FTS update into every Hocuspocus update — explicitly defer that to post-v1.
4. **UX scope.** Confirm what the cmd+K palette shows: page-title results with breadcrumb + snippet, opens the page on select. No in-page navigation / block-level search in v1. No search inside attachments (already out of scope on the map).
5. **No external search infra.** Confirm v1 uses **only Postgres FTS** — no Meilisearch/Typesense/Elastic for v1. (Defer to post-v1 when scale demands.)

**Resolve by:** `/grilling`. Output: the FTS column/index spec, the permission-scoping approach, the accepted freshness window, and the cmd+K UX scope. **Blocked by** ticket 0002 (permission scoping) and ticket 0003 (the `body_text`/`pages` shape).

## Resolution — 2026-07-28

All five questions resolved. Search is intentionally modest in v1 — "find the
page," not "find the paragraph." Postgres ≥15 target (for `GENERATED ALWAYS`
stored columns + GIN).

### Decisions locked

1. **FTS setup** — a **stored generated `tsvector`** column on `pages`:
   ```sql
   search_tsv tsvector GENERATED ALWAYS AS (
     setweight(to_tsvector('simple', coalesce(title,'')), 'A') ||
     to_tsvector('simple', coalesce(body_text,''))
   ) STORED
   ```
   Title weighted `A` (ranked higher than body), config `'simple'` for v1
   (language-agnostic; switch to a language config per-workspace post-v1 if
   stemming matters). GIN index: `CREATE INDEX pages_search_idx ON pages USING gin(search_tsv);`
   Ranking via `ts_rank(search_tsv, query)` (title weight gives natural priority).
2. **Scoping by permission** — **inline**: join FTS hits against the
   effective-permission CTE from ticket 0003 (`can_read($U, p.id)`). Shares and
   group membership are evaluated live; no cache, no invalidation, single
   source of truth shared with the sidebar and doc-load checks.
3. **Freshness** — **accept the ~10s lag**: `body_text` is updated in the *same*
   debounced `onStoreDocument` save path that persists the Y-doc (ticket 0004's
   2s idle / 10s max). The generated `search_tsv` auto-follows. No per-keystroke
   indexing. One consistent lag window with persistence.
4. **UX scope** — cmd+K palette: results show **page title + breadcrumb
   (folder/parent-page path) + a short body snippet**; selecting opens the page.
   No in-page/block-level navigation, no search inside attachments (out of
   scope on the map).
5. **No external search infra** — v1 uses **only Postgres FTS**. Defer
   Meilisearch/Typesense/Elastic until scale demands (post-v1).

### The query (spec)

```sql
-- $q: user search string; $U: user; $W: workspace
SELECT p.id, p.title, p.icon,
       ts_rank(p.search_tsv, q) AS rank,
       ts_headline('simple', p.body_text, q, 'MaxWords=30') AS snippet
FROM pages p, plainto_tsquery('simple', $q) q
WHERE p.search_tsv @@ q
  AND p.workspace_id = $W
  AND p.deleted_at IS NULL
  AND can_read($U, p.id)              -- effective-permission check (owner/admin fast-path
                                      --   OR the recursive-CTE from ticket 0003)
ORDER BY rank DESC
LIMIT 20;
```

`can_read` is the same effective-permission function used by doc-load and the
sidebar (lives in `packages/auth`); owner/admin short-circuit to `true`.

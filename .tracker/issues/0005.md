## Question

The editor is **BlockNote** (decided). This ticket resolves **what v1 ships inside the editor** — the product-level scope of blocks. BlockNote ships a rich default set, so most of this is "accept defaults vs. trim/extend." Land each:

1. **Block-type list for v1.** Confirm the exact set. Recommended baseline (all BlockNote defaults): paragraph, H1–H3, bulleted list, numbered list, todo/checkbox, quote, code, divider, image, file, table. Trim or extend — state the final list.
2. **Nested-page blocks.** A Notion hallmark: any block can be a *link to another page*, and pages can be nested inside pages (a "sub-page" block that opens a new doc). This is central to "nested pages" being a first-class feature. **In or out for v1?** (Recommend in — it's a listed feature — but confirm, because it adds editor + tree-model coupling.)
3. **Slash menu & drag handle.** Use BlockNote's default slash menu and block-drag handle, or customize the slash menu's items/order? (Recommend defaults for v1.)
4. **Custom block types.** Does v1 need any app-specific block beyond BlockNote's defaults? (e.g. a "workspace-group mention," an "attachment gallery," a "kanban" — none of these are in the feature list, so recommend **none** for v1; flag that any future custom block requires ProseMirror schema work.)
5. **Text formatting depth.** Confirm the inline-formatting set: bold, italic, underline, strikethrough, inline code, link. Any others (color, highlight) in v1? (Recommend the standard six; defer color/highlight.)
6. **Markdown input / paste behavior.** BlockNote supports markdown shortcuts and paste. Confirm this is on by default — no decision likely, but state it so the spec is complete.

**Resolve by:** `/grilling`. Output: the v1 block-type spec (a list), the nested-page-block decision with rationale, the inline-formatting set, and explicit "deferred to post-v1" notes for anything trimmed.

## Notes

- The **nested-page-blocks** decision (item 2) feeds back into the data model (ticket 0003): if a page can be nested inside another *as a block*, then the `pages.parent_page_id` relationship and the Y-doc must agree on who owns the nesting edge. Surface this coupling.
- Text-formatting depth is mostly free (BlockNote defaults); the real product decision is nested-page blocks.
